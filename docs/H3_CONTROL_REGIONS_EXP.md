# H3 Fun Control 区域控制与源画面裁剪

`H3 Fun Control · 区域与裁框 (EXP/T8)` 给现有 Fun Control 增加目标区域 MASK 和源画面 crop JSON。
旧 Loader、Apply、默认参数和已保存工作流不变。它仍接收预处理后的控制 IMAGE，不会自动提取姿态、深度或边缘。

区域 MASK 控制采样期的目标视频控制残差，不是生成后贴回图片，也不保证区域外最终画面或生成声音完全不变。
联合注意力仍可能把变化传到其它位置。需要保留原音轨时，继续使用原来的显式音频锁定或最终 mux。

## 导演台操作

在当前镜头的“画面从哪里来”中展开“局部画面控制”，添加一条或多条控制。选择已经预处理好的控制图片或视频，
再选择 Fun Control 模型；列表合并实际 `models/controlnet` 和 `models/model_patches`，也可以填写自选文件名。
这里不要求 Prompt Relay，也不改变共用底模、各阶段内容 LoRA 或加速方案。多条控制按列表顺序叠加，可用上下按钮调整。

“区域、裁框与高级选项”默认折叠。目标区域使用成片画布坐标；源图裁框使用原始控制素材坐标。
界面中的两种框均以归一化数值保存，源裁框运行时根据真正解码的原图尺寸换算成像素，不使用首尾预处理预览图代替。
拖动中实时显示辅助框，松开只保存一次；取消拖动不写入历史。可拖动移动、拖边角缩放，或点击“重新画框”。
源裁框可以超出原图，超出部分补零；预览会裁掉越界辅助线，数值不会被自动夹取。

目标画布从当前服务端编译结果取得。未获得有效结果时明确显示“比例示意”，不把屏幕上的近似比例当作送模尺寸。
控制素材只绑定控制条目，不会自动占用 `@image`、`@video` 编号；同一素材另作普通参考时才按原参考规则编号。
工程保存、复制、撤销、素材重连、ZIP 和收藏模板保留控制草稿及独立条目身份。停用、零强度和未运行阶段的条目不要求完整生成配置。

单采（包括 HyperFlow 原生单 8 步）使用 SINGLE，忽略 LOW/HIGH 开关。标准双采及其它 HyperFlow 配方分别接入实际
LOW、HIGH 画布；两个开关都关闭时仅保留草稿。从冻结 HEAD 仅恢复 TAIL 时只消费 HIGH，未运行的 LOW 不参与当前生成。
原 partial x0／完整输出的放大入口、学习型 3D 放大器、噪声、步数、sigma 及录音 mux 均沿用原路线。

控制视频从原生 `GetVideoComponents` 读取实际 FPS，按 24fps 目标时轴选帧；源不足时可以选择保持最后一帧或明确报错。
IMAGE 端口不携带逐帧 PTS，因此该路线按输入 FPS 作 CFR 假设，不能据此认证 VFR 精确时轴。控制视频的音轨不会进入生成音频链。

## 接入现有工作流

1. 保留原模型、LoRA 顺序、视频 VAE、控制加载器、提示词和采样配置。需要区域控制的阶段才使用新 Apply。
2. 将原 Apply 的输入接到新 Apply，宽高和帧数必须对应这个阶段的实际画布。
3. 可选连接 `region_mask`。白色为完整控制，黑色为无直接控制残差，灰色为相应比例；不连接则保留全域控制。
4. 新 Apply 输出的 MODEL 和 positive 接回原采样链。它不修改步数、sigma、放大器或音频路由。
5. 将 `region_state` 和对应采样器的输出 LATENT 接到 `H3 区域控制 · 采样后审计 (EXP/T8)`，审计的 LATENT 再送原解码链。

新 Apply 第三个输出是 `region_state`，第四个才是 `report_json`；旧 Apply 的第三个输出仍然是报告。
新接线不要把状态口误连到文字显示口。`strength=0` 返回原 MODEL 和 positive，不执行 VAE，也不解析未使用的 crop 草稿。
新区域 Apply 接受任意有限强度，不额外限制为 0–2；正尺寸、32 对齐、帧格和实际计算检查仍保留。旧 Apply 的控件范围和默认值不改。

导演台编译图还会插入 `H3 导演台 · 控制源时轴与几何 (EXP/T8)`，输出原空间 RGB、目标 MASK、源像素 crop JSON 及准备报告。
它只准备输入，不估计深度、姿态或边缘。HyperFlow 分离 HEAD 使用专用 typed Boundary 审计，位于可选 HEAD 保存之前；
普通采样与最终 TAIL 使用 LATENT 审计，不能把 typed Boundary 硬接到 LATENT 端口。

## 区域与裁剪是两个独立坐标空间

`region_mask` 按目标画布的归一化坐标解释。MASK 可以有不同于目标画布的栅格尺寸，空间权重采用像素格面积覆盖率，
再映射到本阶段真实 H3 视频 token。全白和全黑的平面保持精确的 1 和 0，不受栅格不能整除的舍入影响。

`crop_plan_json` 的框则使用输入控制 IMAGE 的原始像素边界坐标：`[left, top, right, bottom]`，右侧和下侧边界不包含在框内。
裁剪不会移动区域 MASK。超出源图的部分补零；翻转、缩放和补边作用于控制 IMAGE，而不是最终生成视频。

例如，对 1280×720 控制源取中间一块，缩放后保持比例补边并水平翻转：

```json
{
  "schema": "t8.h3.control_crop.v1",
  "source_size": [1280, 720],
  "boxes": [[320, 0, 960, 720]],
  "fit": "contain",
  "flip_x": true
}
```

`fit` 可用 `exact`、`stretch`、`contain`、`cover`。`exact` 要求裁框尺寸等于目标画布；`contain` 补边，`cover` 居中裁去溢出部分。
显式 crop 使用双线性像素中心采样和零填充。crop 留空时调用旧 fit 路径，保留旧插值行为；因此显式写一个全图 crop 不等于旧插值的逐位复现。

## 移动区域与帧映射

`boxes` 可以只有一个框，也可以每个源帧一个框。`frame_indices` 可显式指定每个输出帧取哪一源帧；
不指定时按顺序取帧，源不足则保持最后一帧。自定义列表必须覆盖整个输出长度，不能依靠猜测补齐。

MASK 只有一帧时静态广播；MASK 帧数与源帧数相同时跟随 `frame_indices`。其它情况需要给出独立的
`region_frame_indices`，长度等于输出帧数，每个索引指向一帧实际 MASK。它不是秒数或 VFR 时间戳转换。

帧数沿用 H3 的 `17n+5` 网格，宽高为 32 的正整数倍。区域时间权重按照真实 `1/4/4/4/4` 帧组汇总，
而不是把 MASK 时间轴均匀插值到 latent。实际采样画布或时间格不一致会报具体尺寸错误。

## 双采与多个控制

LOW 和 HIGH 各接自己的 Apply，并分别填写实际宽高、帧数和 stage 标签。MASK 可以来自同一归一化区域，
但每个阶段会按自己的 token 栅格重新映射；不要复制另一阶段的 token 行号。源像素 crop 则须对应各自真正连接的控制 IMAGE。

同一 MODEL 可顺序添加多个区域控制，各控制保留自己的状态、强度和时间窗。已有可委托的 block hook 继续调用，
不清除用户的 LoRA、注意力或其它控制。未知组合只提示风险，不自动换模型或更改采样配置。

## 查看实际应用状态

Apply 的报告只说明配置已建立，不能证明采样器调用过控制。采样后审计才显示：

- `residual_calls`：实际观察到的控制残差调用数。
- `gated_calls` 和 `target_row_evaluations`：实际完成门控的调用与目标视频行数。
- `crop_prepared` 与 `crop_consumed_by_observed_control`：裁剪已准备和实际被观察到消费，二者分别记录。
- `preserved_reasons`：无法门控时保留原控制的具体原因。

当前实际残差入口覆盖兼容控制塔和 Core 的 official model patch 路径。缺少可识别目标布局、选用 Morton 非光栅行序，
或旧 native 路径没有可用残差入口时，保留原控制并明确报告区域未应用，不把旁路算成功。
真实缺失接口、张量尺寸错误、NaN、无效 MASK 或坏裁剪数据仍正常报错。

本轮状态是当前执行的观察对象，`portable_cache_identity=false`，不能单凭统计对象授予跨进程 Stage 缓存复用资格。
可识别的自有控制组合另有独立内容身份：核对实际控制权重、补丁顺序、控制源、编码行、区域与裁框、强度与时间窗，
以及真正执行的 wrapper、前置委托和视频 VAE。它只在检查用的模型副本上投影，不会删除实际模型上的用户补丁。
符合这些内容合同的 HyperFlow HEAD 可以持久保存，并在新进程只恢复 TAIL；LOW 与 HIGH 仍保留各自的控制配置。
未知 hook、外部 wrapper 或无法核验的 VAE 继续正常委托，但不获得伪造的可移植身份。

采样期间实际修改自有控制权重、源 RGB、区域 MASK、编码结果或执行代码，会拒绝签发完成记录；
即使外部 wrapper 已让整个模型不可移植，这些可识别内容的完整性检查仍然保留。
派生区域行和原生延迟编码结果会校验，但身份检查不额外执行一次 VAE 编码。

CPU 已覆盖真实微型视频编码器、两种控制塔、普通 Stage 采样、异常恢复、旧全域效果等价、独立多控制，
以及新进程 TAIL-only 与同进程结果的视频和音频张量逐位对照。导演台图和折叠编辑器也已核对。
这些不代替完整训练权重的实际加载、GPU 区域效果、双采完整成片及人审，后者仍需单独验收。
当前没有新增已获人审推荐的成片工作流。
