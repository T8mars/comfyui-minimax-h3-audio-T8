# HyperFlow 导演台组合接入与验收范围

HyperFlow 原始权重走专用加载器，不作为普通加速 LoRA。导演台的五种 HyperFlow 配方与标准双采、FastH3、P7 长片分别保留；开启 HyperFlow 不会修改旧项目的默认采样路线。

首尾图、参考素材、中间关键帧和可选 Prompt Relay 现在按每个阶段重新构建条件。返回 MODEL 的条件节点，其 MODEL 与 positive 成对送入同一阶段；普通提示词不强制使用 Relay。实验接线可用不代表该组合已经完成训练模型的 GPU 画质验收。

## 五种采样路线

| 路线 | 实际区间与 NFE | 阶段交接 |
| --- | --- | --- |
| 单采 8 步 | 0–8，共 8 NFE | 一个 MODEL 与一套条件 |
| 连续 4+4 | 0–4、4–8，共 8 NFE | 同尺寸，直接传递捕获的模型空间 x_sigma，不重新抽噪声 |
| 分离连续 4+4 | HEAD 0–4、TAIL 4–8，共 8 NFE | 独立阶段、效果审计和显式保存恢复；仅 TAIL 恢复执行 4 NFE |
| 低清 8+高采 4 | LOW 0–8、HIGH 4–8，共 12 NFE | LOW 完成结果经已有 learned 3D 放大，HIGH 使用新噪声 |
| 低清 4+高采 4 | LOW 0–4、HIGH 4–8，共 8 NFE | LOW 的 denoised_output 预测 x0 经已有 learned 3D 放大，HIGH 使用新噪声 |

五种路线保留原始九点训练网格和视频／音频 shift 12／3。两个阶段共用底模，各自保留多 LoRA 的顺序与强度。阶段加载复用现有 Fresh Loader，从 Core 的原权重备份只读恢复时间端点，避免后加载的分支把已驻留的另一阶段权重当成原底模；不卸载共享模型或清除用户补丁。

低高清路线从原图片分别准备 LOW 和 HIGH 条件。HIGH 的尺寸接放大器实际输出，并通过现有 TwoPassLatentReconcile 合并放大结果、新 HIGH 模板和声音策略，不直接复用 LOW 的编码条件。

## 素材与声音

| 输入 | 当前行为 | 验收边界 |
| --- | --- | --- |
| 文字、首帧、尾帧、首尾、多参考、Hybrid | 保留原生条件工厂的任务、素材顺序和音频设置，逐阶段接线 | 任务转发及 Core 图接口检查不等于每类任务的训练模型成片通过 |
| 中间关键帧 | 普通或 Relay 条件工厂按当前画布重新编码；两阶段各自使用返回的 MODEL | 实际关键帧位置、强度和画面质量须按路线验证 |
| 原音驱动 | 保留导演台既有的首帧 Avatar 配方；窗口化录音传给各阶段，最终交付使用原录音 mux，而非生成音轨 | 本次不把首帧录音配方扩大为任意尾帧／多参考录音配方 |
| 模型生成声音、参考音色 | 保留既有 native／参考路由，不要求用户上传无关尾帧或驱动录音 | 各参考任务的效果不借用文字单采资格 |

普通视频 mask、单路 Nested mask、视频／音频双路 mask 均沿用 Core 的插值和广播规则；缺失的音频 mask 仍为全 1。连续 HEAD 额外保存原始素材、同一份 prepared noise 和遮罩，TAIL 继续使用它们作为 inpaint 上下文，并注入原始 x_sigma。它不从 HEAD 的临时 clean view 重建已知区域，也不重新抽噪声。NaN、越界权重、无法插值的形状及实际通道错误仍正常报错。

## 断点恢复与组合效果

分离式连续双采支持独立 TAIL 提示词、内容 LoRA、Relay 和 EAV。保存文件中的原始状态、素材、噪声和遮罩同时绑定实际 HEAD 请求及输出收据；路径、SHA、张量清单和完成状态仍检查。未知 callable 可在原进程执行，但不能获得伪造的跨进程身份。

仅 TAIL 恢复不会重跑 HEAD。若当前录音已改变，冻结 HEAD 的素材仍然是旧来源，而当前录音用于新 TAIL 条件和最终交付。导演台报告会列出冻结 HEAD 文件 SHA 与当前录音文件 SHA，并提示：需要整片按新录音生成时，重新生成 HEAD。这两个 SHA 标识不同对象，不能据此宣称录音内容相同。

自有中间关键帧的位置补丁和可选逐图混噪 forward 已接入精确身份检查。检查原生 delegate、实际闭包、运行中的辅助函数和条件快照；只在检查副本上归一化，不清除用户 MODEL 的补丁。普通／Relay、统一／独立混噪及原音遮罩的中间图 HEAD 已通过同版本环境的新进程 TAIL-only 恢复，冻结文件不被改写，不重跑 HEAD 或重抽噪声。

TAIL 可以独立修改中间图、位置或混噪值；这会改变新 TAIL 的请求身份，不被误判为篡改旧 HEAD。实际底模内容或原始 HyperFlow 适配器不匹配，以及冻结状态、文件 SHA 或收据损坏仍报错。未知第三方闭包可在原进程执行，但不能仅凭复制版本标记取得可移植身份；当前检查不宣称跨主机、不同 Core 或运行时版本的恢复资格。

Semantic Bridge、LowVRAM 和 ChunkFFN 保留所选配置。未识别的模型或补丁组合给出风险提示，实际执行错误正常传出，不按名称设准入名单。FastH3 与 HyperFlow 同时提供独立 SAMPLER／SIGMAS，目前没有联合网格协议，因此明确报出接口冲突，不静默关闭其中一个算法。既有 comfy-aimdo 双分支原生崩溃保护仍保留，不自动修改用户的运行环境。

## 本地验证与后续验收

连续采样的 52 项独立 CPU 检查使用真实 Core 50+2 层 tiny 网络、实际采样器和 inpaint，适配器张量与文字为明确的合成测试输入。覆盖独立 HIGH 条件、1+7／4+4／7+1、软／二值／全零及音频锁定 mask、真实跨进程仅 TAIL 恢复、输入篡改、EAV／Relay 调用和取消后下一请求。连续结果与同源的原生单次 8 步逐值一致；原生 FP32 锁定音频对原输入本身存在约 7.45×10⁻⁸ 的误差，不宣称输入音频 latent 逐位不变。

历史 55 项任务／声音“未验证即拒绝”测试完整迁移为阶段条件转发检查，未删除用例。它们检查工厂合同，不把实际由录音解析出的 Ref2VA／Hybrid 改称 T2VA。导演台文件素材、MODEL 配对、原音窗口、HIGH 尺寸与放大入口另有专门图测试。CPU 图验证不运行训练权重。

中间图的实际 8+4／partial 4+4 又分别经过完整 690MB learned 3D 权重、LOW32→HIGH64 的独立条件与两阶段文件保存回读；普通／Relay 共四例。DiT 仍为真实 Core 随机 tiny 50+2、文字与适配器为合成输入，不能据此宣称训练模型画质通过。另有本机 2.8GB 原始 HyperFlow 权重的完整读取与转换检查，不是完整底模推理。

2026-10-22，五种 HyperFlow 路线已分别完成当前 Core 的隔离训练模型 8 秒生成，每片 192 帧、576×1024、24fps；同批标准 4+4 对照、实际控制报告、全部 RGB／PCM／PTS／strict 解码及整批源／Core／权重末尾校验有独立记录。范围见本地开发收据 `c-real8-six-batch-verified-v1.json`。这不等于任意参考／录音组合或整片画质已通过；连续 8 步与分段路线即使 MP4 字节相同，也不据此宣称所有内部 latent 相同。

另有中间关键帧 HyperFlow OFF／ON 训练模型对照，实际重新编码／位置投影消费及网络进度到 8 已被观察；两片完整 240 帧 RGB／PCM／PTS／strict 通过，见 `h22-D-HF-media-v1/actual-v1/collection.json`。

同日，包含中间图与区域裁剪的固定 HEAD 已在全新进程实际加载，仅执行绝对区间 4–7 的 TAIL 四步；没有重跑 HEAD 或重新抽噪声，HIGH 区域与裁剪均有非零消费。完整 120 帧、1024×576、24fps 的冷恢复 MP4 与原热续采 MP4 字节相同，两份完整音视频解码记录一致。原后置读数器曾因大写 SHA 与小写字符串比较误报；原失败保留，以严格 64-HEX 规范化的只读补充重核原文件、WS、原始 AV、末尾校验和进程退出，没有重跑生成。证据为 `h22-cold-tail-postflight-v2/actual-v1/collection.json`。

这只授予该固定配方在当前同版本环境的冷 TAIL 兼容资格。热执行未保存最终 raw TAIL，不能宣称两次 latent 逐位相同；也不推及跨主机、其它模型／组合、性能或人工画质。普通原生 8 步、标准 learned 3D 双采 4+4 的独立中间图 OFF／ON 对照另已实际完成，两路线各完整 240 帧音视频及真实条件／位置消费机械通过，见[中间关键帧验收范围](DIRECTOR_MIDDLE_KEYFRAMES_EXP.md)。其它组合与最终人工观看／试听仍分别验收。
