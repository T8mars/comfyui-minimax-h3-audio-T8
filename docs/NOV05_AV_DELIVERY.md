# 音频时间原点与导出校验

本增量保持 Output Trim 的旧默认：`source_time_origin_seconds=0`、
`audio_boundary_policy=legacy_duration`。旧调用仍从 `round(start*rate)`
取 `round(duration*rate)` 个 PCM 样本，不悄悄改变历史工作流。

需要拼接多个连续音频窗口时可显式选 `absolute_endpoints`。此模式分别把
全局起止时间映射为最近 PCM 样本端点，再减去源时间原点；44.1 kHz / 24 fps
的半样本采用 ties-to-even，补偿浮点加减的 4 ULP 半样本舍入误差。时间过大以至
无法分辨单个 PCM 样本时明确报错，需同时重设请求和源的时间基准。

`source_time_origin_seconds` 是**输入 IMAGE 和 AUDIO 共同的源时间原点**，
不是只移动音频。`start_seconds` 仍是非负全局时间，源原点可正可负。例如源从
5 秒开始，截取全局 5.25 秒，视频从本地第 6 帧、48 kHz 音频从本地第 12,000
样本开始。请求在源原点之前或视频帧数不足会报错，不能凭空填视频帧。
本节点不处理两条输入具有不同 PTS 原点的情况；调用方须先对齐。
音频尾部不足仍按已有行为补零，报告明确列出复制和补零样本数。

报告同时记录实际绝对/本地样本端点、请求绝对端点、源原点、补零数及舍入策略。
在 legacy 模式下请求端点与实际读取端点可能不同。`frame_count` 保持独立的
离散视频交付合同；不为了凑音频长度改视频帧数。

基础 AV Decode 在浮点 IMAGE 转 uint8 之前检查非有限值，并检查真实 Core
音频解码输出。未知 VAE 类名仍委托原来的解码接口一次，实际几何或数值错误
明确抛出，不引入模型白名单。

Safe AV Save 在原有隔离编码、完整解码验证、原子发布之前，再核实际帧数、
尺寸、24 fps、音频率/声道、轨道零原点和表示终点。AAC 解码可能含不足
1,024 样本的尾部填充；报告区分实际解码样本、逻辑 PCM 长度和填充，不把
编码填充当作丢失词尾或新声。源 PCM 和 RGB8 分别记 SHA256。媒体元数据检查
不能证明同规格另一成片的内容身份，也不能替代人审。

已验证：真实 tiny Core video/audio VAE 数值异常及恢复；32/44.1/48 kHz、
正/负/零原点连续窗口逐样本重组；实际非零 PTS FFV1/PCM 输入解码、裁切再
导出零原点 MP4；真实 AAC 解码/表示终点；错误长度成片拒绝、中断后清理重试；
现有导演媒体隔离/失败恢复与 H27 交付合同回归。旧默认 PCM 结果保持一致。

这些是 CPU 数学、真实 Core 接口和真实 codec 回归，未使用训练后 GPU 模型，
不等于唇音同步、语义词尾、人声听感、显存峰值或速度提升验收。测试用合成短片
不是最终人审影片。`docs/NOV05_LOCAL_SFX.md` 另述外部 PCM 候选。

本轮另有 TaoMate-HD、双采噪声、NAG、端点与声音候选的真实训练模型成片，均经
同一保存器的完整交付检查及独立浏览器播放验证。这补充真实媒体消费者证据，仍
不把播放器能播、时长正确当作人工画质或听感通过。

局部音画合成另修正了一个原声截尾问题：候选音频短于来源时，原实现把两条音轨
同时裁到较短长度，连 `audio_intervals=[]` 的视频局修也会丢失原声尾部。现在来源
PCM 决定输出样本数，未编辑尾部完整保留。候选没有覆盖实际修补区间或淡化范围时
报出缺失样本，不能把不存在的候选当静音填入修补区。等长输入、已覆盖区间的混音、
声道和采样率转换保持原算法；报告分别列出来源长度和候选可用样本数。
