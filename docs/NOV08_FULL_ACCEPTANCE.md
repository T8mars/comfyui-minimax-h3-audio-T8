# 原 27 方向的补充验收

原始27方向的有限验收已完成，PH3专用图像栈按用户要求排除；最终真实反馈见本页
“最终反馈与版本交付”。自动检查、训练权重计算、性能与人工画面／声音评分分开记录。
下文保留返修过程及当时未通过的状态，不将失败实验追认为成功。未知模型和LoRA组合
继续委托原计算路径；v1.105.0不自动部署或重启用户Core。

## 已修问题

- Safe AV Save 曾将有限浮点原声中超出±1的采样判作“来源削波”并阻断保存。
  实际AAC原片的321536个解码值中仅4个超出满刻度，峰值约1.047。现在直接将有限
  float32采样交给既有f32le/AAC编码路径，记录峰值和超满刻度数量，不限幅、归一化
  或改动输入张量。共用H3-World辅助函数的历史默认仍限幅，只有本保存器显式选择
  保留浮点幅度。最新Core的109项相关回归、Core0.41.1/0.43.0各42项回归及实际
  原片的Clock→Trim→保存均通过；编码前PCM逐位核对，有损AAC不承诺解码后位相同。
- 局部修改的候选音频较短时，合成曾截掉未编辑的原声尾部。现以来源样本数决定交付
  长度；只有所选区间或交叉淡化确实访问缺失的候选样本时才报错。新增 5 个实际 PCM
  反例，保留等长混合算法。
- 工作流检查器遇到空的运行时模型下拉列表会自身报错，现正确处理空列表默认值。
- 工具生成的三参考验收图曾使用 1/2/3 号动态端口，原生 schema 实际声明 0/1/2。
  已更正该验收图，检查器也会核对实际 Autogrow 声明；不改变用户模型选择或运行节点。
- Source Clock/Conform/Map 仍存在自设 4096 帧、2GiB RGB/PCM 上限，合法长素材被
  提前拒绝。已移除这些上限及对应 UI 人为最大值，保留真实尺寸、源范围、坏数据、
  内容身份和取消检查。实际 4102 帧、16×16 原生解码及 32×32 同源准备/控制映射已复现旧失败，
  修复后连同既有时间轴消费者在三套 Core 上各 27 项通过；原生 Lanczos/8-bit RGB
  数值路径没有改变。实际资源不足仍由底层计算报告。
- 真正加载外部 LanPaint 后，发现时钟适配曾按整个 Core H3 文件的 SHA 拒绝接口
  未变的新版 Core。现按实际纯时钟函数及 live 绑定核对；三套 Core 的真实依赖各
  7 项通过，包括实际 tiny AV、LoRA/hook 保留、失败恢复与无关源码变化。依赖仅在
  隔离目录加载，用户 Core 未安装或修改；早期 5 项依赖缺失的跳过记录保留。

新增 native DoRA 回归覆盖输入/输出两种 magnitude 轴、文件 alpha、正负强度、重复
加载和卸载后的原始权重恢复。Core 0.41.1、0.43.0、0.44.0 各 4 项通过。LoKr 另有
4 个真实 Core 矩阵前向回归，均为明确的小模型代数/生命周期范围。

同一原生 4 步训练模型请求，完整交付 96 帧/4 秒，单进程连续五次实际运行：

约 0.1589 秒；另计本地同步 JPEG 编码。这不是 WebSocket/网络/浏览器端到端吞吐

63.5–65.3 GiB；冷加载、权重交换和 Python 工具开销均影响结果。

另用原配方首区间作有限前向探针，实际观察全部 50 个 block 的 attention/FFN 分块
从 8 切到 4，确认逻辑配置没有被静默忽略。只比较该区间内的前向资源，不把它当成
新的完整电影或与整请求峰值混用。

12 秒室内长链在全新自有进程按同参数恢复，实际 DiT 前向为 0、CUDA 分配峰值为 0；

把“0 新采样”写成“恢复没有时间或内存成本”。花园片和室内片均保留完整三窗结果。
