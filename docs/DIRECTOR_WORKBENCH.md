# 曜石导演台工作台

从 ComfyUI 左侧栏“导演台”进入。左侧选择镜头，中间编辑提示词和镜头设置，右侧管理素材、查看输入或播放成片；底部可生成当前镜头或按顺序生成全部镜头。原技术检查、导出和项目操作仍可从工具菜单访问。

## 模型与采样

顶部“模型与采样”中，底模、文本编码器和视频／音频 VAE 共用一组选择。旧项目默认保持单采；选择“双采样”后，一采与二采各自有独立的有序多 LoRA 列表，可设置文件、强度、启用状态和顺序。复制列表不会把后续修改绑定在一起。全片默认只影响跟随全片的镜头；切换本镜独立设置后不再随全片变化。点击应用才提交窗口修改，取消保留原配置。

目标分辨率按 MP 总像素选择，预检回显实际 LOW/HIGH 尺寸；按 H3 网格及学习型放大器规则对齐，不保证恰好等于输入的像素总数。双采使用一个底模分出两阶段 LoRA 链，先低分辨率采样，再学习型 3D latent 放大和高分辨率细化。标准双采与 FastH3 V2 独立路线互斥；缺文件和真实尺寸错误仍会明确报错。

LoRA 已配置、视频已生成不等于所有 patch 都成功生效。部分裁剪底模与 LoRA 组合可能在 Core 日志中报告形状不匹配；保留用户选择并提示风险，应检查实际 patch 日志。任意 LoRA 组合、人物一致性、声音、口型及连续长片质量都需要单独验收。

工具区的“导出 HyperFlow 分离图 EXP”只针对当前镜头已选择的 `continuous4plus4separate` 路线：根据当前有效模型、素材、种子与阶段设置编译，下载可在 ComfyUI 画布编辑的原生工作流。完整图分别显示 HEAD/TAIL 采样、独立 Relay Plan 与 EAV；选择“仅 TAIL 恢复”时，导出图只读取已验证的 HEAD 冻结文件并采 TAIL。导出不排队、不更改项目或旧图；当前旧 `continuous4plus4` 一体路线不会被伪装成分离图。导出前仍需通过当前镜头的模型/素材预检，恢复图的路径和 SHA 必须对应真实冻结文件。现阶段仅有 CPU 结构与导演台回归，尚未完成此新导出图的原生浏览器保存重开、真实预训练 GPU 音画和人工画质/接缝验收。

## 提示词、素材与成片

- 新手模式整段粘贴本镜提示词；高级模式分整镜描述和时间事件。两种草稿分别保留，仅当前模式参与编译。
- 高级时间事件使用整数帧输入（24fps），旁边显示秒数；新事件接上条结束帧，默认延长48帧。工程仍保存兼容的秒值。旧的非帧对齐时间会明确标记，必须自行修正，不自动舍入；录音选区和本镜总时长不因此改成整数帧输入。
- 工程包保留两种写法的初始化状态；导入旧包时，已经存在的文字或刻意清空的草稿都不会因首次切换模式被另一稿覆盖。
- 全片设定和共享素材跨镜头复用；图片、视频、音频统一从素材区加入，再分配用途或在光标处插入对应引用。
- 放大提示词编辑不会被后台任务完成或失败消息覆盖；关闭编辑后仍可打开任务状态查看详情。
- 导演台各类弹出窗口统一在当前视口内水平、垂直居中，不跟随点击位置或页面滚动偏移；窗口随可用高度收缩，长内容在窗口内部滚动。下拉菜单和 `@` 候选仍跟随对应控件，不当成独立窗口。
- 生成成片与输入素材分开显示。已有结果通过持久媒体回执恢复；失败不会删除此前成片，也不会自动重采样。没有结果的镜头不会显示伪造成片。
- 成片区可选择历史版本并明确“采用此版”。新生成不会替换采用版本；采用版本缺失时不会偷偷换成最新片。复制镜头只复制设置与素材引用，不继承原镜头采用版本的身份。
- 成片区“编辑采用范围”核对采用片的实际帧数和帧率，设置包含的入帧与不包含的出帧，并显示秒数。范围仅影响整片串播与导出，不修改原片或生成时长；可恢复全片、撤销。复制镜头或更换采用版本时清除旧范围，避免把旧片的隐藏裁剪用于新片。
- 同一镜头有两版成功成片后，可用“A/B 对比”并排播放。两版核对后保留固定媒体副本，A 控制播放与拖动、B 跟随；只比较共同播放长度、只听一路声音，不承诺动作逐帧对应。关闭对比不改变采用版本。
- “版本详情→复制此版设置为新草稿”创建独立服务端工程，保留当时项目设置与此镜实际种子，不替换当前页，也不继承旧成片采用状态。旧版本缺完整快照时不猜测还原；模型文件、自动模型选择或环境变化仍可能改变重新生成的结果。其它镜头保留当时草稿，不称它们全部是最终生成参数。
- “整片串播”按项目镜头顺序读取每镜采用版本。未采用、文件缺失或损坏会定位到对应镜头；准备成功后保存固定 SHA 的媒体副本及清单，不随原输出覆盖、草稿重排而变化。该副本位于导演台用户数据的 `film_media`，相同内容复用；一次最多准备 20 GiB。此阶段是播放列表，切镜可能有加载间隙，不是已编码完成的整片 MP4，也不代表音画质量通过。
- 素材区“筛选”可按名称、类型、全片／本镜范围、最近查看查找；不修改实际排序与 `@` 编号。“素材库”另支持全工程名称／素材 UUID 搜索、图片／视频／音频类型、全片共享／本镜已加入／尚未加入本镜筛选。筛选不是重新分配用途，也不会将整个库加入生成。
- 在提示词、全片设定、事件文字或放大编辑框中输入 `@`，可按素材名或 `image`／`video`／`audio` 编号查找本镜候选。↑↓选择、Enter 或点击插入、Esc 关闭；只替换当前输入的查询词，前后文字保留。候选使用实际引用编号，最多先显示 12 项；更多可继续输入名称。未加入本镜的素材先从库中指定用途，不自动激活。
- 全片设定引用本镜独有素材时，会明确提示共享范围；放大编辑框内的共享变更暂存，只有“保存并返回”才生效，取消不改工程。新增共享参考引起编号变化时，既有引用按素材身份重映射，不错指其它图。
- 顶部“更多→布局”可调整列宽，或进入写作／审片专注模式；布局只保存在本浏览器。

## 保存、恢复与副本

生成期间可以继续编辑并保存项目；保存的是当前编辑稿，不会更改已提交任务的冻结输入。保存期间新增的编辑仍保留，但需要再次保存才进入服务端版本。离线不自动补交保存或生成，请恢复连接后手动重试。

普通“另存副本”只复制编辑设置及素材引用，不继承原项目成片版本、采用身份和裁剪；原工程与视频保留。需要携带采用成片时使用工程 ZIP。另存响应丢失后再次点击会核对同一个目标项目，不暗中创建多个副本。若目标副本又发生变化，明确提示核对，不自动覆盖。

本地草稿保护与服务端保存分开报告。浏览器存储受限或配额不足时，即使远端保存成功，也会提示本地恢复保护不完整；请保留项目链接，并导出尚未保存的编辑。支持 Web Locks 的浏览器会隔离同时打开的导演台草稿；其它浏览器用独立页面键转存恢复内容。浏览器存储完全不可用时不能保证关闭页面后恢复未保存数据。

生成提交失联后重试使用原请求 ID 和冻结输入；即使先保存或修改提示词，也不会把新配置当成另一个请求悄悄提交。旧格式恢复记录会尝试读取服务端原快照；无法核对时先查看原任务，必要时明确确认放弃重试身份，再手动发起新生成。放弃不取消原任务，可能重复生成，因此不会自动执行。

## 镜头排序与选择生成

镜头列表支持拖动及“镜头操作→上移／下移”，已有成片仍跟随原镜头。勾选后在底部“选择生成”中生成选中镜头，也可仅生成尚无成片或配置已修改的镜头。缺完整历史快照时不会猜测是否修改，请手动选择；更改标题、编辑未激活提示词草稿和禁用的 LoRA 行不会被当成有效采样变更。

新批次冻结目标镜头顺序及逐镜种子，重排草稿不改变已提交批次。旧 Core 必须更新并重启后才能识别此协议；页面会先核对版本，不能让旧后端忽略选择而生成全部。任务列表可定位镜头；“本镜完成后暂停”不会中断正在生成的镜头或其它 Core 任务。

底栏“任务列表”打开居中的独立非模态窗口，不复用提示词编辑弹窗。打开时每 5 秒查询当前项目记录及旧冻结批次，可关闭自动刷新或手动刷新；关闭窗口、切换工程或离开当前标签后停止查询。迟到响应不重开窗口，状态刷新不重建提示词编辑器或抢焦点；网络失败标记上次结果，不重发生成。继续／暂停仍使用底栏已有入口，任务窗口本身不提交、重试或中断任务。

自动草稿检查只检查当前编辑模式的基础缺项。文件与尺寸预检、依赖检查分开进行，不加载模型；实际预检尺寸仅在草稿未变更时显示，不能把目标 MP 当作已验证宽高。

## 文本分镜导入

在左侧“镜头操作 → 导入文本分镜”粘贴文字，或选择本机 UTF-8 的 TXT／Markdown 文件。文件只在浏览器读取，不上传。明确格式如下：

```text
# 开场 | 4秒
人物走近镜头，微笑。

# 回答 | 3.5s
人物说：“你好。”
```

点击“解析并预览”逐镜检查名称、时长和完整提示词；不猜测自然语言时长、不自动拆台词或动作。正文若以 `# ` 开头，用 `\# ` 转义。正文缩进及内部换行保留，仅去掉分镜边界空白行。格式错误会标明行号，不能只导入合法部分而丢弃错误内容；一次最多200镜，文件最多1MiB。

确认后只追加新镜头到列表末尾，可一次撤销；旧镜头、全片设定、全片模型和既有成片不被覆盖。新镜头使用新手写法、显式时长、模型生成声音，跟随全片设置，不复制当前镜头独立的首尾帧、录音或采样。实际时长与路线依赖仍须预检，导入本身不生成视频。

外来 `@image1`／`@video1`／`@audio1` 及原生媒体标签不能证明素材身份，预览会明确转成 `@missing_…` 占位，需勾选确认后导入并重新绑定；不会碰巧引用本工程同编号素材。原输入文字保留在导入框内。预览后修改文本或切换工程必须重新预览；取消不改工程。

## 创作收藏与参数复制

“更多 → 创作收藏”管理当前工程的四类收藏：提示词片段、镜头模板、采样配方、素材组合。收藏随保存项目、JSON 和工程 ZIP 迁移；每工程最多200项、总计2MiB。重命名或删除收藏可撤销，删除收藏不删除原素材，也不修改此前已应用的镜头。

- 片段：先在全片设定、本镜提示词或事件文字中放置光标；选中文字时收藏选区，否则收藏整段。使用时插入光标处，不覆盖选中文字。`@` 引用按素材 UUID 对应新编号；无法对应时明确预览 missing 占位并要求确认，不碰巧引用同编号素材，也不自动把本镜素材提升成全片共享。
- 模板：保存本镜两种提示词草稿、事件时间、素材用途及生效采样/D3快照；使用时在当前镜后新建独立镜头。不会复制旧镜头种子、采用成片或裁剪状态，不更换当前工程的底模及全片提示词。共用画幅仍跟随当前工程。素材缺失时整项拒绝，不偷偷套用部分内容。
- 配方：保存生效采样、多 LoRA、D3、画幅和时长。使用或“直接复制当前参数”都先选择字段及当前/勾选/全部镜头，再预览确认；默认仅采样与 LoRA，不改底模。被复制的采样/D3成为独立设置。全片共用画幅开启时，按镜头复制画幅会拒绝，避免意外影响未选镜头；时长变化不自动缩放事件，需重新预检。
- 素材组合：保存本镜素材的稳定身份和顺序。套用时图片/视频加入本镜参考，音频只加入素材栏，不自动指定驱动或音色，也不改首尾帧或全片共享。组合是复用工具，不保证人物身份或跨镜连续。

应用前是纯预览，确认后为一次可撤销编辑，不自动生成。改变参数/目标、修改草稿或切换工程后需重新预览。工程包导入时，收藏及其素材/模板事件身份随新工程同步重映射；缺失引用仍保持显式缺失。原生媒体标签在收藏复用中不能证明稳定身份，会作为待绑定内容提示，不猜测对应素材。

## 从成片取帧接下一镜

在“镜头成片”选中成功版本，点“取帧接下一镜”。核对并固定这一版完整媒体后，输入从0开始的整数帧号，默认真实末帧，点击“提取并预览该帧”。服务端按解码顺序生成原尺寸 PNG，不做裁切、放大或浏览器截图；不支持未经转换的非方形像素、旋转视频。文件、SHA或帧范围错误会拒绝，不换成其它成片。

可以应用到紧邻的下一镜，或在当前镜后新建一镜。下一镜已有首帧时必须明确勾选替换；它的旧素材、采用成片、音频用途、提示词和尾帧保留。有尾帧的镜头保持首尾模式。新建镜头使用默认设置和空提示词，不继承旧成片身份。应用后可一次撤销镜头编辑；素材库和磁盘中的独立图片仍保留，不删除文件。

预览会创建输入文件，但确认前不会加入工程或覆盖镜头；关闭/取消或迟到请求均不自动绑定。相同工程、源视频 SHA 和帧号复用同一图片身份。取帧只是静态接镜，不传递原片音频、运动轨迹或长片 latent，不保证人物/动作连续，也不自动生成下一镜。

图片素材同时记录来源完整视频 SHA-256、整数帧号和帧率；随项目保存、重开及工程 ZIP 迁移保留，不绑定旧工程路径或旧镜头 UUID。它是可追溯的来源记录，不是外来工程包真实性签名，也不要求把来源视频一并打包。旧取帧图片只有在重新解码并核对像素一致后才补写来源，来源冲突不覆盖。

## 整片 MP4 导出

准备好“整片串播”后，展开窗口下方“导出整片 MP4”。选择输出宽高并确认编码规格：24fps H.264、48kHz 双声道 AAC，按冻结清单的整数帧范围硬切。不同画幅等比缩放并补黑边，不裁切、不补帧、不加叠化、不做响度归一；原始音频会按明示的交付规格重新编码，原片不变。无音轨的镜头只有明确勾选后才补静音。目前不自动转换非 24fps 成片，也不宣称片段之间叙事或人物连续。

导出使用独立 CPU FFmpeg，不加载模型、不占用 ComfyUI 生成队列；同一 Core 一次只执行一个导出。关闭窗口后可用“上次导出”查看进度或下载文件。网络响应不明时先核对旧请求，不自动重发；Core 重启后的未完成导出标为中断，由用户明确另起任务。下载前会验证导出文件 SHA，损坏文件不会冒充成功结果。

## 带素材工程包

“更多 → 工程包 ZIP”用于迁移完整创作工程；原“导出项目”仍仅输出 JSON。先点“检查清单与大小”，默认包括当前工程素材库的输入文件与每镜明确采用的成片，不包括未采用历史、模型权重、运行日志或未知扩展字段。未生成的镜头仍保留为草稿；已有采用版缺失或损坏不会自动换片。取消“包含已采用成片”可明确导出仅含输入的草稿包，包内不再携带旧采用状态。缺输入会明确报错，不偷偷丢弃素材。

确认后生成 ZIP。采用成片以完整源文件打包，裁剪范围只作为工程设置保留，裁剪范围外的画面也在包内。提示词、素材、媒体原始元数据和模型文件名仍可能包含私人信息，分享前自行检查。最多20GiB媒体/2048个文件；检查与迁移需要本地副本空间，不加载模型、不提交生成。

导入先上传检查清单、路径、实际大小、SHA与媒体可读取性，再明确确认创建全新工程。项目、镜头、事件、素材及采用版身份重新分配，引用顺序和 `@` 编号保留；原工程与当前页不覆盖。导入的采用成片独立复制到 Core 输出目录，重新打开也可播放/串播；不冒充本机重新生成或具备历史配置快照。模型需在新机器另行安装，并重新检查依赖。

“恢复上次导入请求”使用已登记的相同目标身份，网络结果不明时不会直接创建重复工程。已编辑过的导入工程不会被重复导入覆盖。ZIP危险路径、链接、重复/缺失文件、异常压缩比例或坏SHA会拒绝；原文件均不删除。未知扩展字段需保留原 JSON 另行核对，不默认夹带到可分享包。

## 保存、切换与网络恢复

放大提示词编辑框使用独立的临时草稿，不直接写入工程。刷新后重新打开同一栏目，可选择恢复或丢弃；恢复只填入编辑框，点击“保存并返回”才提交，取消/关闭则丢弃本次临时编辑。恢复按当前素材身份重排引用，已缺失素材标为 `@missing`。浏览器无法保护临时草稿时会提示，并在离开页面前请求确认。弹窗中的按钮、下拉框快捷键不会撤销背景工程，文本框仍使用原生文本撤销。

浏览器存储满或禁用导致旧稿备份失败时，打开/导入工程不会直接替换当前稿。先点击“导出当前草稿备份”，确认文件已保存，再明确继续；此期间出现新编辑或更换载入目标，旧继续动作失效。

项目保存与本地草稿分开：保存请求期间的新编辑保留为草稿，不冒称已经上传。并发版本冲突不会自动覆盖服务端。另存成功才切换项目身份。

刷新后若先恢复本地副本，会显示其基于的服务端版本及“未核对服务端”；该副本可能包含未保存编辑，不代表必然有新改动，也不代表已与最新服务端同步。真正从服务端载入时显示服务端版本，不再立即误标为待保存草稿。

连续打开项目只接受最后一次有效请求；载入期间出现新编辑时保留当前草稿，提示重新载入。普通上传和素材重连均固定原项目身份，切项目后不会把迟到的上传结果绑定到新项目。取消任务只影响原任务的状态跟踪。

全部生成在提交前冻结项目快照并按顺序执行。每次生成使用请求 ID，响应不明时重试相同请求而不是直接重复排队；刷新恢复已有任务只查询状态。这不等于跨 Core 重启的 latent 阶段续算。

切换项目会使旧批次的后续提交意图失效，即使随后切回同一项目也需重新明确继续；已经提交的任务仍保留原身份并跟踪。取消请求失败或服务端未确认取消时，继续核对任务，不把短暂未知状态报成“已取消”。

任务列表保持屏幕居中，空态/少量任务按内容收缩，长列表限高滚动。极窄窗口的顶部操作允许换行；长模型设置的应用/取消栏固定在弹窗顶部。

## FFmpeg 与更新

更新 GitHub 源码后重启 ComfyUI，并刷新导演台以加载新增后端和前端模块。本次源码更新不改变版本号，也不表示 Registry 已重新发布。

导演台的音视频素材识别、完整解码核验和成片取帧使用独立 CPU 媒体进程，每次操作结束即退出，最多同时运行两个。媒体库异常退出或检查超时会明确报错，不自动重试、不写成功回执；既有原片不改动。单次检查最长30分钟；等待空闲检查槽也有30分钟上限。取帧仍按原尺寸输出 PNG，并核对源片 SHA，不裁切或改变采样算法。这是媒体进程故障隔离，不代表所有第三方编解码器已无缺陷。新增后端需要重启 Core 才会生效。

这里“不自动重试”指单次媒体检查不在内部循环重试。后续批次状态查询仍会按原逻辑重新核对尚无有效回执的媒体，不会因此重新提交生成任务。读取媒体在线程中等待，不阻塞页面接口的事件循环；这不等于新增了立即中断解码的取消按钮。

生成前检查已安装的 FFmpeg：支持 `T8_FFMPEG_PATH` 指向可执行文件；随后检查 PATH、整合包的 `ffmpeg/bin` 和已安装的 imageio-ffmpeg。不会自动下载程序，显式配置无效时会报错而非悄悄换程序。

自动化状态测试使用真实前端模块与隔离网络替身；CPU 图编译、无头浏览器交互和实际 GPU 成片是不同层级的验证，不能相互替代。
