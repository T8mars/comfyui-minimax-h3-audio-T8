# Pika H3 Flex 双采（实验）

Pika双采使用相同的完整6步LCM时间表，在LOW和HIGH之间切换尺寸和MODEL分支。它不是把原有Euler 4+4改成6步，也不是Pika云端的高清upsampler。

## 4+2与3+3

新增 **H3 Pika Flex · 双采4+2 / 3+3**。连接方法：

1. 共用一个底模加载节点，从它分出LOW和HIGH两个MODEL分支。每个分支可串联多个现有LoRA加载器，分别选择Pika适配器、其它LoRA、顺序和强度。不接`model_high`时沿用LOW的MODEL。
2. 分别建立LOW和HIGH的H3条件与AV潜空间。使用相同原生时间网格，各自连接对应尺寸的提示词、首尾帧、参考素材和遮罩；`positive_low`和`positive_high`分别接入，不把旧尺寸条件冒充新尺寸。参考图可以按用户设定保留独立尺寸。
3. 选择已安装的`minimax_h3_latent_upscaler_3d_fp16.safetensors`，设置`low_evaluations=4`得到4+2，设置3得到3+3。节点不会下载模型，也不会在缺少学习型放大器时换成普通插值。
4. 主输出`av_latent`送AV解码和保存。`low_clean_prediction`仅供观察低尺寸阶段的中间预测，不能作为完成的视频或最终音频。

共6次采样求值、5次中间新噪声。视频sigma为`[1,36/37,12/13,4/5,4/7,1/3,0]`，视频/音频shift分别12/3，CFG1。4+2在视频sigma`4/7`处接入HIGH，3+3在`0.8`处接入HIGH；音频仍继续原来的联合采样，不能在LOW结束时提前冻结。

阶段切换保留同一随机数生成器。LOW结束时在Core做非零终点反缩放之前捕获真实状态；HIGH的原生条件和clean source正常准备，只替换求解器起始状态，避免二次混噪。跨尺寸时先将末次clean视频预测转换到VAE坐标，实际调用学习型3D潜空间放大，再在HIGH坐标加入边界新噪声；音频使用原来的带噪中间状态。边界噪声只抽取一次。

同尺寸运行可用于与连续6步核对，不执行放大。节点保留用户MODEL补丁和LoRA；未知组合不代表已获画质认证，实际缺失接口、时间形状不符或内核错误会按原错误报告。

## 普通Pika模型6+3（新增实验）

除下方可选2K配方外，另提供不加载2K Refiner的常规尺寸路线：

`Pika完整6步 → 完成的AV潜空间 → 学习型3D放大 → 普通Pika模型末3步细化`

默认512×288生成，放大到1024×576（约0.6MP），并非必须输出2K。使用已有节点即可接线：一采用Pika准备节点及原生SamplerCustomAdvanced运行完整6步；完成的AV潜空间送学习型3D放大器，再用二采潜空间协调节点接入新尺寸条件。宽高从放大器输出直连高尺寸条件，避免手动尺寸不一致。

二采MODEL从同一个原始底模独立分支，加载普通Pika FL2VA LoRA；两路均可独立串联多个LoRA、调整顺序与强度。二采再次用Pika准备节点提供LCM与12/3时钟，通过原生SplitSigmas设置`step=3`，取`low_sigmas`输出，实际视频sigma为`[0.8,4/7,1/3,0]`，BasicGuider/CFG1。二采有独立种子，在已完成的一采视频上由Core初始化一次混噪，总共9次前向；它不继续4+2的中间噪声状态。

二采潜空间协调使用`second_pass_audio_source=first_pass`、`second_pass_audio_strength=0`，并连接二采音频校验节点；最终视频保存使用一采原音。工作流同时保存一采原片、只做学习型潜空间放大、再细化3步三个结果，便于判断额外采样是否有收益。

这条路线没有加载Open Regenerate、2K Refiner、Turbo或Sharp。它是本项目的实验组合，不是Pika官方发布的高清配方，不承诺多3步一定更清晰或保持身份。原有2K图和4+2/3+3方案保留，各自选择；现有节点默认值与算法不变。

当前新增路线的47项相关CPU检查通过，其中3项直接运行tiny Core的T2VA/FL2VA/Ref2VA完整6+3。所选FL2VA完整训练模型已在GPU运行9次前向，交付124帧1024×576，整图388.67秒，Torch峰值已分配显存约8.55GiB；没有据此扩大到其它任务、硬件或画质资格。实际执行学习型3D权重，二采音频latent精确相同；三个保存点使用同一一采原音，最终AAC数据包与时间戳也相同。35节点前端图已保存、重开并核对全参数和连线，三段视频浏览器完整播放及控制检查通过。该新增普通6+3样片现已收到独立反馈，按自己的binding/媒体SHA核对后，画面与声音均通过（“都不错”）。不是沿用此前2K或4+2反馈。

## 完整Pika6 + NV细化3（可选2K路线）

这条路线总共9次前向，与总共6步的4+2/3+3分别选择：

`Pika完整6步 → 完成的视频潜空间 → 学习型3D放大 → 完整Open Regenerate配方3步 → 最终成片`

使用现有Pika准备节点和原生SamplerCustomAdvanced，完成的一采潜空间直接进入既有细化流程。细化MODEL从原始共用底模单独派生，加载完整Refiner+Turbo+Sharp合并权重及独立Sharp曲线分支，不从已叠Pika的MODEL继续追加同款加速权重。详见[完整配方](OPEN_REGENERATE_2K.md)。两阶段仍可分别追加用户选定的多个LoRA。

细化使用Euler、CFG1、sigma`[0.909375,6/7,2/3,0]`、时钟1/1；不再次套Pika的12/3。最终封装保留一采生成的声音；细化模型里的VAE静音只是锁定的上下文。该组合不保证逐像素保持一采端点、身份或修复已有运动模糊。

## 当前验证边界

114项相关CPU检查通过，包括同尺寸所有1..5分段与连续6步的最终视频/音频逐位一致，3+3/4+2跨尺寸、首尾帧/参考条件、多LoRA独立分支、锁定音频/画面、局部遮罩及异常清理。另直接观察真实Core的参考视频payload，确认LOW/HIGH分别收到各自参考尺寸及时间网格。CPU的放大器是明确标注的测试替身；学习型权重已在下列双采GPU案例中实际调用。

当前RTX4060Ti16GB、INT8底模、8组注意力/8块FFN的所选记录如下。均保留124帧、24fps，最终1024×576（约0.6MP）；耗时为整图执行，不含独立进程启动。

| 所选案例 | 实际前向 | 整图秒数 |
| --- | ---: | ---: |
| 文字双采4+2 | 6 | 243.20 |
| 首尾帧原生单采6步 | 6 | 396.98 |
| 首尾帧双采4+2 | 6 | 249.06 |
| 首尾帧双采3+3 | 6 | 283.77 |
| 图片参考双采4+2 | 6 | 252.63 |
| 图片＋视频参考双采4+2 | 6 | 734.66 |

双采案例实际观察到LOW/HIGH不同尺寸的前向、5次新噪声和学习型放大器调用。首尾帧三个对照的Torch峰值显存相近，本组不能证明省显存或任意硬件上的加速。相同种子在不同尺寸下会形成不同运动轨迹，不能把姿势差异自动当作错误或宣称逐帧保真。

完整Pika6+NV3另外生成了2560×1440、124帧成片，实际9次前向，整图3293.75秒。50个Sharp曲线分支各执行3次；封装前音频逐样本一致，最终AAC数据、数据包时间戳及音轨属性也与一采相同。该路线中的一采文件与独立原生6步对照逐字节一致。另有5帧训练GPU短探针，观察一采/细化9次前向中所有50层的FC1每次各调用8次，核对共享底模切换后的实际分块；此短探针单独记录，不作画质样片。

图片＋视频参考使用本地已生成的24fps动作视频及图片，LOW/HIGH各自构建对应条件，已在完整训练模型上生成1024×576、124帧成片。参考视频增加了条件处理与采样计算，不能沿用单图案例的耗时。

原七份前端工作流已在独立浏览器完成加载、保存、重开和参数/连线核对。四组审片对照的八段展示视频均单独播放到浏览器结束，逐帧/定位、半速、全屏、单路音轨、反馈导出和异常提示检查通过。用户反馈已与原审片binding和各组媒体SHA逐项匹配，四组画面与声音均通过；T2VA选择4+2，首尾、参考及2K细化组评价“差不多”，未选统一最佳方案。这份反馈不延伸接受新增的普通模型6+3。原三份已审Pika单采图、导演台旧默认及原779个节点定义保持不变。
