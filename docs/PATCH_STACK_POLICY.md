# 用户补丁组合策略

2026-09-17 源码更新。本文覆盖旧文档中“组合未经验证所以禁止执行”的说明。
当前合并范围与历史验证边界见[源码同步说明](GITHUB_SOURCE_SYNC_20260917.md)，不另发布Registry版本。

## 使用许可与效果验证分开

全部自有节点不再仅因已有或后加 LoRA、KJ Sage、SageAttention、Sol-Attn、
block/attention/MLP forward、hook、wrapper、callback 或 injection 而主动阻断。
组合未经效果验证，意味着警告和风险由使用者承担，不意味着用户不能运行。
旧 `enforcement`／`reject`／未验证组合确认控件兼容读取，但不能恢复这种准入禁令。
实验引导／Turbo OOD 的旧确认开关也只作提示；明确选择实验模式才会改变配置，
缺省步数、sigma、音频、学习型3D网络和已接受的双模型接缝方案不随本策略改变。

这不等于承诺所有算法同时生效。多个节点修改同一个选择器时，后续显式选择可以
取得该入口；原 callable 能组合委托的保留委托，不通过清空补丁伪装兼容。
第三方 hook 不调用 `original_block` 时可能绕过分块、Relay 或 EAV，报告应记录
实际调用与覆盖不足，不把“成片返回”写成“所有优化均已验证”。

## 具体行为

- **LoRA**：保留普通权重补丁和已有注入链；追加补丁维持原顺序。文件不存在、
  A/B矩阵配对或真实尺寸不符、选定加载器未实际映射其目标仍正常报错。
- **两个独立计算分块**：Chunk FeedForward／MLP Activation Chunk 保留已有
  callable owner，并在可委托路径插入分块。和 Plan＋Upscale 的时间分块不同。
- **Low VRAM Attention**：已有外部 block/attention forward 的层保留外部实现，
  不强行覆盖或拒绝；这些层可能没有本节点头分组。查看实际安装／保留层数。
- **Relay／EAV／SLA／VDN／FastH3／TST 等组合**：前置、后置及采样末尾审计
  都不能仅因未知组合阻断；覆盖不足标记 `unverified`。可组合的 attention delegate
  保留原参数和 mask；已有 mask 与新增偏置合并，不偷偷删除 mask。
- **CLIP／VAE 和缓存入口**：未知可执行对象不被序列化为伪造的可移植身份。
  外扩条件对象可绑定当前 provider；重开时对象缺失需要重建条件。
  Qwen前缀缓存缺少适配时保留所选CLIP并报告缓存未启用，不禁止正常编码。
- **原始 Sol 注册**：`sol_attn_minimax_v2.py` 依照用户“原样注册”要求保持原文件，
  不在本次修改第三方实现、参数或其自身内核合同。

建议先加载模型、串联需要的 LoRA 和所选注意力节点，再接 T8 分块／采样器。
这只是便于阅读的接线方式，不是唯一强制顺序，也不是任意组合的画质或提速认证。

## 保留的真实错误

仍校验缺少输入、非 callable、形状／dtype／设备或底层API不满足真实计算要求、
坏数据／NaN、坏SHA、错文件和越界路径、MODEL–CONDITIONING配对及节点自有
receipt／运行时token／不可变缓存资产损坏。需要的内核未安装或实际执行失败，
错误正常传出；不吞异常、不伪造成功、不静默替换成另一个算法。

环境审计中的组合风险只作警告；真实输入错误、缺失运行时和配置的资源保护不变。
需要完整采样证据的不可变缓存不接受伪造完成记录。

## 缓存与断点恢复注意

已识别组合保留原内容身份校验。无法识别的可执行 MODEL／CLIP／VAE 状态使用
新的执行身份，**不能跨运行复用旧缓存**；外扩VAE采用新的 `execution-…` 子目录。
当前调用内仍校验权重、LoRA字节及已选对象是否发生替换，但不认证 opaque 对象的
内部可变状态。不要把未知组合的失败缓存搬进认证链或冒称断点恢复已验证。

`resume_existing=true` 不是关闭坏SHA、参数身份或缓存完整性检查。
未知组合出现不能复用时，重新准备当前任务，不是禁止使用该组合。

## 开发与测试要求

### 已审查源码的 Python 调试元数据差异

当前 KJ／Sol 适配器只忽略 live `.pyc` 与同一原源码新编译结果的调试行／列范围表差异。
源码／AST／内核 pin、执行指令、递归带类型常量、异常表、flags、参数与闭包布局、
源码路径和位置仍严格匹配；原 globals、默认参数、实际 callable owner 检查不变。
不删除用户插件的字节码、不重新编译替换其对象、不认证修改后的执行代码。

15 个完整 CPU 测试范围共384项通过，含实际 KJ Relay 路由、dense 数学对照、
历史 KJ 分块前向、FastH3 V2 Sol 配置及非视频／音频边界、五个双采接缝范围。
未知 Sol callable 仍保留为未认证 delegate：检查不调用它、不授予内核或跨进程缓存资格。
CUDA 未初始化；此结果不代表 CUDA 内核、全部工作流或画质验收。

规则已写入项目 `SKILL.md` 顶部。新增节点或更新已有节点时，检查入口、运行时、
composer、返回错误的分支、末尾审计和缓存入口，不能只改一个抛错字符串。

测试必须验证旧补丁保留、原 callable 实际执行、默认数学路径不变、真实异常正常
传出、未知组合不误用旧缓存。静态清单工具 `tools/audit_patch_stack_policy.py`
只是源码／候选入口清单，不证明任意组合兼容。`tests/test_patch_stack_policy.py`
包含 tiny Euler、实际CPU SDPA、LoRA字节、DiT委托、TST拆解及外扩条件等行为测试。
实际 Core 注册／schema、工作流校验与完整GPU成片人审分别记录。

外扩测试仍使用真实跨进程lease；相关CPU批次须串行运行，不能并发后把锁竞争
误判成采样故障。不要为测试通过而移除生产锁。

**本次边界**：没有新增整模型GPU成片或任意组合质量保证。检查发现正式目录部分
SelfLift调用接口与现有实现不一致，相关失败必须单列，不能删测试、xfail或以CPU
注册通过替代功能通过；也不能借本策略覆盖恢复已暂停的研究源码。
