# 导演台：只读候选失效说明

在「更多 → 镜头证据与规则」中点击「只读检查候选失效原因／参考编号／计划时长」。
这是当前草稿的解释，不会采用候选、写项目、处理图片、加载模型或提交生成。
旧项目和没有新分字段快照的旧候选继续按原来的总签名判断是否失效。

新候选在原总签名之外，记录编译时实际消费的十个分量的 SHA：全片设定、
本镜原稿／用途、参考顺序、被引用素材、事实证据、创作意图、明确依赖、
有效规则、编译选项和输入格式。修改参考绑定时，也可能改变被引用素材集合；
两项都显示，不把原因强行简化成一个。这里不保存旧提示词副本，也不重签旧候选。
旧候选没有历史分量时显示未知；分量与总签名声明矛盾时不冒充准确归因。

参考编号来自现有编译器的实际草稿槽计划，分别显示 Picture、Video、Audio。
同一个有声视频的画面槽和声音槽不相同，也不能据此证明两个说话人声纹锁定。
报告不显示素材的服务器路径，不认证文件当前字节或实际编码后的槽布局。

时钟并列显示用户请求秒数／帧数、原网格对齐帧数／秒数和交付裁齐帧数。
这些是编译计划，不是源 PTS 测量或生成成片；不会解析自由文本替用户改时长。

## 草稿冲突和缓存的区别

另一个入口保存后，旧入口保存仍按原版本机制返回冲突，未保存稿保留。
用户可手动另存副本或重新载入；检查按钮不自动合并、重载或覆盖任何一方。
另存编辑副本沿用原政策，不继承原工程的成片采用和裁剪。

候选签名一致只解释当前稿件，不是 MODEL／Stage 的跨运行缓存命中。
真正 Stage 复用仍需要已有完成回执、manifest、tensor、权重和完整配置身份检查。
显式 Cold 选择旧资产也不认证今日 LOW 参数与旧资产相同。
未知 callable 仍可运行／委托，不授予跨运行缓存资格。

当前本地已验证候选 pending／stale 显示与两个实际入口的冲突、手动另存。

第三镜、保存和重开后，前两镜正文、采用ID、成片字节与固定回执均保持。
该检查新增采样为0；登记只标记外片，不伪造生成祖先，也不认证Stage缓存。
