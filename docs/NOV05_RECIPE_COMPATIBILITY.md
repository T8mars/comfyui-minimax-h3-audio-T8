# 配方兼容与动态 PDD 身份修复

本轮检查实际 Core 的 LoRA 解析/矩阵前向、PTD 音频时钟及专家选择、ER-SDE 的实际
前向次数、PDD 分阶段消费者。名字和文件头仍只是诊断，不能证明完整算法生效。
用户的底模、LoRA 顺序/强度、第三方 owner 和旧 sigma 默认保持。

动态 PDD 的一个真实问题已复现并修复：Core bypass 注入会保存
`original_force_forward` 并启用模块的 `comfy_force_forward`；旧 PDD 身份投影只接受
原四个字段，采样计算完成后把合法的第五个字段当成未知状态，末尾报告 MODEL 身份
变化。修改只读投影，支持经过验证的布尔备份和实际启用状态，在私有克隆中恢复标志。
未改 live MODEL、权重、采样数学或 Core 文件。真正换函数、换绑定 owner、非法 flag、
额外 callable 仍不能认证完成/缓存；未知组合不因此得到伪造的可移植身份。

三套本地 Core 的选定首轮结果如下。两个旧版本目录是源码副本，实际模块路径和 SHA
记录在私有结果中；不以目录名代替运行来源证据。

0.41.1 能计算 PDD 头，但原生文件检测未从 `pdd_steps` 还原基础 channels；只补声明
channels 也不够，构造器不会按 bank 数创建堆叠头。新诊断回归分别实际触发这两个尺寸
错误，保留失败证据；没有修改用户文件/安装 Core 或把失败改成 skip。现有 T8 动态
PDD adapter 入口是独立路线，经修复后的真实消费者回归；它不能被描述成旧 Core
原生 baked 文件加载已经支持。使用烘焙文件需具备该实际构造接口的 Core。

针对修复的消费者组包含 LOW/HIGH、0/0.5/1 强度、Relay/EAV、冷热及重建身份、额外
用户 LoRA 保留、失败后下一请求、真实篡改反例。另有实际运行反例确保普通 PDD 不依赖
另一个原生 bypass 缓存适配器的源码目录准入；沿用 PDD 自己的闭包和实现内容绑定。
每版最终该组 69 项通过，CUDA 未初始化；另有结果/保存恢复与五组双采门禁 109 项通过。
这些批次不与前表相加为独立功能数量。两个旧 Core 的模型、检测、bypass 三个源码文件
均与本地 Git 对应提交逐字比较一致（统一换行）；其它实际导入来源另记 SHA。
源级与 CPU 测试不替代全尺寸训练权重/GPU/整片人审。
