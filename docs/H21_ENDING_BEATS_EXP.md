# 导演台明确结局与局部节拍

在导演台的“镜头证据与规则”中，展开“声明式 Prompt 规则”，点击“填写明确结局与局部节拍”。它只填写空表单，不覆盖已有草稿，不自动添加规则、采用候选、保存或生成。

填写本镜的起始状态、最后必须看见的结果、允许变化和局部节拍。例如，有钥匙时写“人物用手中原有钥匙打开箱子，最后箱盖保持打开”；无钥匙时写“人物没有钥匙，最后箱盖始终关闭”。这是用户选择的两个独立创作条件，不会自动判定持物、结算游戏规则或认证模型一定遵从。

音乐片段同时写清全片区间与本镜局部时间，例如“所用 Audio1 是歌曲 13–18 秒；本镜局部 0–2 秒举剑，2–5 秒收势”。模板不会裁切音频、推断节拍、改变采样或事件时钟，也不强制切换 Prompt Relay。实际使用的 Picture/Audio 标签由用户按已绑定素材核对。

只在字面对白栏填写确实需要说出的原文；无对白时保留“无对白”。规则说明、节拍标签和创作声明不是台词。声明也不会自动变成观察事实、确认的上一镜末态或字幕来源。

填写参数后，沿用现有流程：添加规则快照 → 编译待审候选 → 审阅并显式采用。不采用时原稿继续生效；可以回退到原稿。保存重开仍保留快照与采用状态，修改参数后沿用既有候选失效检查。

当前 CPU 合同覆盖两个相反结局、节拍文字的字面保留、空表单保护、候选采用/回退及工程保存重开。它不证明视频中的开箱结果、持物连续性、音乐同步或声音表现；同素材、同 seed 的生成对照与人工审片仍需分别验收。

自有无头 Chromium 也已实际点击该入口，通过原 guarded API 和工程存储完成候选采用、保存重开、回退及已有草稿保护。测试使用独立本地 HTTP 端口，没有使用用户浏览器、请求视频生成或安装新环境。
