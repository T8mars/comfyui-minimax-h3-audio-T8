# 完成阶段复用与返修恢复

`H3 Stage · Sample or Reuse / 采样或复用 (T8 EXP)` 复用真正完成的 AV 阶段，使用已有 Stage Save/Load 的不可变文件、完成记录与 SHA 校验。它不把 Creator 的计划声明当作缓存命中，也不另建镜头队列。

## 接线与使用

导演台的“模型与采样”窗口现有“已完成采样阶段”选项，支持全片默认与当前镜头独立配置。旧项目缺省仍逐次采样。选择复用后，编译器在原采样边界接入本节点，保留原模型、LoRA 顺序、sigma、随机源、学习型放大和输出接线；任务结果显示实际命中、首次保存或未认证但正常执行。编译成功本身不代表命中。

普通原生 AV 工作流也可直接替换 `SamplerCustomAdvanced`，五个原生输入和前两个输出不变，`stage_context` 现在可选。无显式上下文时，从实际连接的 MODEL/SAMPLER/SIGMAS/AV 建立检查描述，不重新创建采样配方。未知执行栈使用原对象正常采样，不保存伪造完成凭据；采样开始后报错直接传播，不自动重跑。无上下文且禁用复用时 `stage_result` 为空。

Creator 可把已有 Workspace 接到可选 `creator_workspace`，选择与 Shot Select 相同的 `run_position`/`variant_index`，并把 Shot Select 的 seed 接到 NOISE。每镜内容及实际采样输入共同决定身份，无关镜头编辑不使本镜失效。把 `stage_result` 接到已有 Creator Run Receipt，可核验实际完成阶段归属；解码失败仍记录失败，不能据采样已完成把视频标记成功。声明型 Segment Cache Plan 继续只报告声明匹配，不冒充执行命中。

目前自动描述覆盖已适配的原生 AV 采样边界；专用整段执行节点和没有可移植身份的外部组合仍走原执行，不承诺自动复用。显式 Stage 上下文沿用各自已实现的适配器。

在现有模块化工作流中，以本节点替换 `H3 Stage Sampler + Result`，连接原来的 NOISE、GUIDER、SAMPLER、SIGMAS、AV LATENT、STAGE_CONTEXT。输出与原 Stage Sampler 对齐，可继续接下一阶段、Stage Save、解码及视频保存。

- `disabled`：默认，仍实际采样，不创建复用索引。
- `reuse_completed`：先校验当前请求及完成记录；一致时直接返回保存的精确 tensor。首次执行正常采样，成功后保存新记录。
- `refresh`：明确重新采样并生成新记录；旧阶段文件、旧成片保留。

报告中的 `verified_hit` 表示本次扩散调用为 0；`source_denoiser_evaluations` 是原记录的采样次数。`miss_saved` 表示本次确实采样后保存。`uncertified_executed` 表示所选用户模型、补丁或采样器仍正常执行，但本组合没有足够身份依据进行持久复用，不会伪报命中。

阶段采样已经完成而后续解码、编码或磁盘交付失败时，重新运行相同输入即可复用阶段，继续处理后面的解码／保存。外部索引每次入队重新检查；坏 tensor、坏 SHA、缺失或不完整完成记录报出真实错误，不自动把孤立文件当完成结果。`refresh` 可重新计算，旧证据不删除。同一请求已有进程占用时明确报告忙碌。

## 哪些改动会失效

身份绑定实际底模和已加载权重、多个 LoRA 的顺序及强度、条件中的实际参考内容与次序、源 AV/遮罩/元数据、seed、sigma、CFG、阶段合同和数值实现。

同名 LoRA 文件重新加载为新内容后会失效；文件名本身不是身份。若上游仍输出旧 MODEL，本节点看到的是仍在执行的旧权重，不会私自替换模型或读取某个猜测的文件名。更换父 take 使后继实际源 tensor/条件改变时，后继失效，无关联阶段仍可复用。旧成片保留为历史，不删除。

导演台仅在用户开启复用时改接已适配的采样边界；Creator 仍需按上面的接线使用实际消费者。未接线的任务没有自动恢复。声明型 Segment Cache Plan 的 `declaration_match_unverified` 及 `verified_reuse_count=0` 保持原含义；现有长视频双采恢复继续使用其原来的阶段存储及已接受画面续接合同。

## Qwen 前缀缓存是另一层

现有 Qwen visual-prefix KV 仅存在于进程内 CPU LRU；它不保存 AV，也不表示某镜头已经采样。提示词正文重新编码，完全一致的视觉前缀才可能复用。

本轮修正同一 CLIP 包装器持续使用期间的身份：除 Core patch UUID 与源码合同，还绑定实际 encoder/tokenizer 对象、执行设备、dtype，以及参数／buffer 的版本元数据。更换 encoder、常规原地更新权重、重设执行设备或 dtype 后重建 KV；编码前重新计算，不能凭旧 tokenize 阶段的 key 命中。这里只读取 tensor 元数据，不将 32B 模型复制回 CPU 或每次散列全模型。

该缓存仍依赖 Core 正常模型／patch 更新接口。绕过 PyTorch 版本计数器直接修改 `.data`／外部内存的插件，需要主动清空缓存或改变现有 `cache_epoch`；不能把进程对象身份当作任意外部内存改写的内容证明。未知 encoder 保留原执行，旁路 KV 优化。

真实 32B NVFP4 编码器复测发现，Core 低显存加载会在每次请求中重建参数对象；若只按加载后的对象 ID 查找，会持续 miss。现在先检查请求之间的修改，记录本次正常加载／编码结束后的状态，让同一包装器的下一次请求保持逻辑身份。换编码器、tokenizer、设备、dtype、补丁或常规原地权重更新仍失效；多份参考的 LRU 和正文重算保持。

本机指定 896×512 参考，CPU KV 约 187 MiB：首次建 KV 5.25 秒，后续约 1.78 秒，原生暖编码约 3.39 秒。224×224 小参考没有净速度收益；不把冷加载编码时间当缓存加速倍率。参考图、模型、设备及正文不同都会影响收益。真实权重输出与原生输出有浮点舍入差异，此项不承诺逐位相同或下游视频画质通过。

## 验证范围

新增用真实 tiny Core AV sampler 验证首次采样、精确命中、多个非零 LoRA 的实际加载与采样、顺序/强度/同名改内容失效、父源依赖、无关阶段保留、解码失败后的阶段恢复、新进程重建请求后的零采样命中、公开节点接线及坏文件处理。Qwen 使用真实 Core Llama 层和 KV 消费者验证权重更新后重建，视觉嵌入采用明确的微型测试夹具。

这些是 CPU 消费者与完整性验证；不冒充训练大模型画质、GPU 性能或人审通过。没有改变已接受的 4+4 长视频接缝算法、学习型放大器、音频或旧默认参数。

后续指定 GPU 验证已经补齐原生单采及导演标准 4+4：完整 INT8 H3、非零 EMA LoRA、分头注意力与分块 FFN，首次各阶段真实采样后故意让解码失败，重试分别核验完成阶段、以 0 次新增采样保存 96 帧带音频视频。标准双采仍经过原学习型 3D 放大和 HIGH 条件重建。单采还与未接复用节点的原生 Core 进行训练权重对照，采样张量、完整解码画面与音频逐位相同。

阶段核验包含完整模型内容读取，并非零耗时：本机指定单采命中核验约 110 秒；标准双采 LOW/HIGH 各约 101/98 秒。这是失败恢复和跳过采样的证据，不承诺任意设置都有净加速。完成阶段也不等于人工接受某个版本；旧成片和用户选定版本继续保留。

任务完成记录会保存阶段状态，Core 重启后仍可从原回执显示；失败交付保持失败，弹窗提示已保存阶段及明确重试操作。专用整段配方未接自动适配时，编译报告明确提示保持原恢复方式。

实际第一步取消不会产生完成记录；下一请求可重新完成采样，再以 0 次新增采样恢复交付。额外训练模型对照中，INT8 底模配非零 EMA LoRA 在原生 Core 的冷态与暖态两次重采样结果不同；未接复用节点的原生第二次结果，与本节点连续重采及取消后重试的结果逐位相同。该组差异不是本节点新增的取消差异，具体底层数值原因尚未隔离。缓存命中返回先前已完成的精确结果，不保证它等于同 seed 重新采样的结果；需要新采样时选择 `refresh`。没有为此改变用户 LoRA、Core 加载策略或采样公式。
