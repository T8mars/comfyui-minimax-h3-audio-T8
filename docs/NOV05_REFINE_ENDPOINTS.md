# 按实际交付范围约束二采首尾（实验）

`H3 Refine · Delivered End Conditions` 放在最后一次潜空间放大／Reconcile 后、
细化采样器前。开启后，它给覆盖最终交付首尾帧的原始 latent 时间单元设置原生
denoise mask，让采样器使用该来源条件。默认关闭；关闭时原对象直接通过。

`delivery_start_frame`、`delivery_frame_count` 必须与 Output Trim 的最终画面
窗口一致。例如原生输入 124 帧、交付前 120 帧，应填 0、120；不能把未交付的
第 124 帧当作用户看到的尾帧。H3 的时间单元并非每个都覆盖相同帧数，节点按原生
1/4/4/4/4 的分组映射端点，不简单地固定最后一个 latent。

- `first_frames` / `last_frames`：从实际交付窗口两端各约束多少帧；0 关闭对应端。
- `endpoint_strength=0`：使用原生已知条件；增大至 1 允许完整重绘。
- 原有更强的视频保护不会被解除；音频 mask、音频 tensor 和来源 latent 不变。
- 重叠端点只合并保护区域；必须先得到实际放大后的几何，再应用本节点。

原生 VAE 的时间感受野会影响邻近 RGB；这是采样中的 latent 条件，不能保证首尾
RGB 逐像素相同，也不能承诺全片不闪烁。节点不在生成后粘贴画面，不进行潜空间
端点偏移或失败的 post-sampling bridge，不修改已接受的 4+4 长视频默认路线。

CPU 回归覆盖关闭恒等、已有 mask 合并、音频不变、120/121/124 帧尾部映射、
窗口越界与真实 Core Euler 消费者。已执行的训练模型对照采用同一份一采结果、同一学习型
放大结果、同一二采种子及 sigma，分别关闭／开启端点条件，并保留二采前视频供
对照；画质与动作是否自然须看指定完整成片，不能仅凭端点差值通过。

实际图共运行一次 Pika LOW6 和两路 HIGH3，观察到 12 次网络前向；二采前、关闭、
开启三份均为 1024×576、120 帧 AV，并通过完整解码；三份完整解码后的 PCM 也
逐样本一致。三份指定画面已通过人审；其它素材的首尾动作或画质仍需实际验收，
不能仅凭 mask 设置推断通过。
