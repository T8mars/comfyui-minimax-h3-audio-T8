# 参考编码与缓存实测边界

复用现有 Qwen Reference Prefix Cache 与 Reference Package，不增加缓存层、修改 attention、替换音频或迁移旧工作流。缺省仍为 `report_only`；只有显式选 `memory_lru_exp` 才缓存参考前缀，提示词仍重新编码。

## 单次 CPU 编码观察

使用已安装的 H3 Qwen3-VL NVFP4 AWQ、同一张参考图及 448×256 RGB。低显存配置在当前 Core 下将 CLIP 放在 CPU；不是 RTX 4060 Ti 的 Qwen GPU 基准。

| 请求 | 耗时（秒） | 实际行为 |
| --- | ---: | --- |
| 首次原生完整编码 A | 65.98 | 未使用前缀缓存，首次页面／计算冷态 |
| 首次建立前缀缓存 A | 99.06 | miss；先编码参考，再编码提示词 |
| 同提示词 A 再编码 | 35.94 | hit；不是返回先前 CONDITIONING |
| 更换提示词 B | 36.73 | hit；文本重新计算 |
| 原生完整编码 B | 43.00 | 无前缀缓存，进程／权重已暖 |
| 改参考图局部 RGB | 61.87 | miss；内容指纹变化，旧条目被淘汰 |

只是一轮六次编码，不是重复统计或视频端到端测速。与更可比的已暖原生 B 相比，缓存 B 约少 6.27 秒；不能用首次 65.98 秒宣称稳定节省一半，也不能把该比例称为视频生成加速。首次建缓存的额外成本必须计入。

实际前缀约 51.27 MiB，限 512 MiB／1 条；进程 RSS 约 17.7 GiB，其中绝大部分是模型而非缓存。两次命中、两次未命中、无 bypass／超预算拒绝；缓存与模型在测量结束卸载。CPU 内存不是显存，也不是全系统内存峰值。

原生与缓存输出的 token 标签完全一致；两份提示词的 relative RMS 约 5×10⁻⁸，最大绝对差分别约 0.000168／0.000107。因不同计算形状产生舍入差，不声称与原生 bit-exact；同一缓存输入重复调用逐值一致。比较阈值在执行前固定，不为通过而修改。

音频参考这里只增加 Audio 标签，没有 Qwen 声音编码或新声纹资格。修改参考内容会失效，不能凭相同文件名复用。不同 LOW／HIGH 参考尺寸也可能产生不同前缀，不能把单尺寸命中率外推到双采完整图。

## Reference Package

同图同尺寸，CPU 原生 VAE 的一次创建约 15.19 秒，保存后的读取、完整 SHA／producer 校验与路由约 6.98 秒，复用时没有再次 VAE encode。改 RGB 后独立重建约 15.35 秒；其源、latent 和 manifest 都改变，拿旧 SHA 读取新包会拒绝。两包往返逐值一致，实际 VAE load_device 为 CPU，0 扩散 NFE。进程记录 CUDA_initialized=true，不能称为严格 CUDA 隔离测试或 GPU 编码资格；该事实与实际 CPU VAE 放置分别保留。

GPU 路径首次编码后因 Core CausalConv3d 将权重转为 channels-last-3d，被原可移植身份检查拒绝。该失败保留；现在仅对原生 5D 浮点 channels-last-3d 张量按逻辑 NCDHW 字节分块校验，每块不超过 4 MiB。旧连续布局的身份不变，不修改权重数值或物理布局；任意转置、未知非连续子类、过大的单行、NaN／meta 仍拒绝，producer／源码／hook 检查不删除。实现源码变化本身仍会使依赖它的旧执行缓存需要重建，不伪造旧 producer。

同一 GPU 上的一次原图／改 RGB 两包序列已通过实际 create → save → load → producer 校验 → route：创建分别 17.40／19.11 秒，读取及完整校验分别 10.44／8.85 秒，复用不再 encode。两个 producer 一致，改源的内容、latent、manifest 失效，往返逐值一致；实际 load_device 为 cuda:0，峰值 allocated 约 4.92 GiB，结束卸载自有模型，0 扩散 NFE。这只是一个尺寸的参考包资格，不是跨设备数值相等或整视频加速保证。

新增 5 项身份合同及 128 项受影响 producer／缓存／接缝合同通过。首次批次中的 26 项因旧目录 `.pyc` 调试源路径缺失失败，原红证据保留；仅这 26 项在独立 fresh-pycache 下重跑通过，不删除旧字节码或放宽生产源码门。这里共 133 个唯一合同，不重复计数。

## 使用取舍

频繁改提示词且参考内容、尺寸、模型／补丁不变时，可显式使用现有前缀缓存观察收益；单次生成仍保留缺省路径。Reference Package 继续明确绑定原生 producer 和源内容。未知 hooks／调度／非 H3 CLIP 保留原编码、报告 bypass，不获得持久缓存认证。

本次没有重采样视频、运行全仓旧 CPU 测试矩阵、改采样步数或证明整个工作流加速。CPU Qwen、CPU／GPU 单尺寸参考包与受影响身份门分别记录；不据此另加 LRU 或强行启用所有旧工作流。
