## 使用

更新本项目GitHub源码并重启相应ComfyUI，才能获得新增的`H3 Pika Flex · 双采4+2 / 3+3`节点；仅导入JSON不会安装Python节点。普通模型6+3和完整2K6+3使用既有节点，单独选择。

选择已安装的H3底模、匹配的Pika FL2VA或Ref2VA LoRA、VAE、文本编码器，以及`minimax_h3_latent_upscaler_3d_fp16.safetensors`。已有模型无需重复下载。上传或替换LoadImage的首尾／参考图片；图片加视频图还需选择自己的24fps参考视频，避免把其它帧率直接当作24fps解释。模型、人物图片和审片视频未收入仓库。

两阶段共用一个底模加载器，分别串联多个LoRA，独立设置文件、顺序与强度。相同上游设置可能被Core复用，仍可分别修改；不会为未知组合增加模型白名单。

4+2和3+3使用新增双采节点，LOW输出只是中间预测，最终声音随联合采样完成。普通模型6+3先在512×288完整生成，再经学习型3D放大到1024×576，二采用Pika末3步LCM，sigma为`0.8 → 4/7 → 1/3 → 0`、时钟12/3、CFG1；一采声音锁定并保留。目标尺寸在放大器修改，高尺寸条件直接跟随宽高输出。它是已接受指定样片的实验组合，不是Pika官方高清配方。

2K6+3使用完整Open Regenerate合并LoRA和独立Sharp曲线分支，Euler3、时钟1/1，最终封装保留一采声音。它与普通Pika6+3使用不同细化模型和配方，不能只把尺寸调小来互相替代。

普通6+3同时保存一采、只放大、再细化三个结果；2K图同时保存一采和2K结果。用户认为几组结果相近，未选统一最佳方案；不保证额外3步对所有输入都有收益。

数值接线、CPU/GPU和人审范围见[用法](../../../docs/PIKA_DOUBLE_SAMPLING.md)。本次GitHub源码更新不代表新的Comfy Registry发行包已经发布。
